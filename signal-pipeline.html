⏱ The Monday run

One issue, end to end

  1. 7:00
    Agent · wake

    The scheduled task fires

    A fresh Claude agent starts with zero memory of past weeks. Its entire brief — sources, editorial bar, voice, schema — lives in one prompt file, SKILL.md.

  2. 7:01
    Agent · setup

    Picks the issue number

    Lists the existing signal-issue-NNN.json files and takes max + 1. No database, no state — the folder is the system of record.

  3. 7:02
    Agent · research

    Reads the week in AI

    Web-searches the past 7 days across arXiv, lab blogs (Anthropic, DeepMind, OpenAI, Meta AI), and top tech press. Skips press-release recycling and vendor noise.

    More on this
    On thin news weeks it widens to 10 days and prefers under-the-radar tooling over forced "breaking news." Hard rule: never fabricate numbers — ballpark figures get labeled (illustrative).
  4. 7:08
    Agent · curate

    Curates to the Signal shape

    3 headline stories · 5 quick-hits · 1 fun fact · 1 chart · at most 3 outbound links. Every story leads with one plain-English "why you'd care" sentence.

    More on this
    The five quick-hits deliberately vary in shape — a big number, a question, a verdict, a money line, an observation. Stories get the house colors in order: orange, sage, pink. The chart must carry real signal or it gets swapped for a different story.
  5. 7:11
    Agent · build

    Writes the JSON, runs render.js

    One JSON file is the source of truth. render.js turns it into four outputs: the interactive page, an email-safe twin, Medium-ready Markdown, and a regenerated archive.

    More on this
    Voice rules are baked into the prompt: friendly explainer (Morning Brew DNA, but smarter), inline jargon glosses, no hot takes, no vendor cheerleading. Writing the new index.html is the tripwire that sets publishing in motion.
  6. 7:12
    Machine · trigger

    The LaunchAgent notices

    A macOS LaunchAgent (com.signal.autodeploy) watches index.html. Within ~60 seconds of the render finishing, it fires deploy.sh — no human, no cron babysitting.

  7. 7:13
    Machine · publish

    Push, then Pages rebuild

    deploy.sh commits and pushes to GitHub using keychain credentials. GitHub Pages rebuilds the site in about 30 seconds.

  8. 7:14
    Machine · live

    The issue is live 🎉

    New issue page + refreshed archive, served free from GitHub Pages. Total infrastructure bill for the entire stack: $0.

  9. 7:15
    Human · enjoy

    Chris reads the report

    The agent's sub-250-word report lands: story teasers, local file links, the live URL. Nothing to approve, nothing to run.

    More on this
    The one optional step, whenever convenient: paste the Markdown version into Medium and set the canonical URL (3–5 minutes). Medium's API can't set canonicals programmatically, so this stays human — and it keeps all SEO credit pointed at the archive.
🧭 Who owns what
🤖 The agent · editorial

A full newsroom in one scheduled task

Why it mattersResearch, curation, writing, and rendering — the entire editorial process — happen with no human in the loop, to a consistent quality bar, every single week.
  • Fresh agent every Monday 7am; the whole job is specified in SKILL.md — sources, editorial bar, JSON schema, voice rules
  • Wide-net research: primary sources first (arXiv, lab blogs), top press second, recycled PR never
  • Fixed shape every week: 3 stories, 5 quick-hits, 1 fun fact, 1 chart, ≤3 links — constraints keep quality high
  • Self-verifies the outputs, then reports back with the live URL
⚙️ The machinery · publishing

Publishing is a reflex, not a task

Why it mattersThere is no deploy step to remember and no pipeline to maintain — the operating system itself watches for a new issue and ships it.
  • macOS LaunchAgent watches index.html and fires deploy.sh within ~60 seconds of a render
  • deploy.sh: stage → commit → push, with credentials from the macOS keychain
  • GitHub Pages rebuilds in ~30s — free static hosting, zero servers
  • Everything logs to .autodeploy.log; manual bash deploy.sh is the fallback
🙋 The human · taste

Chris is the editor-in-chief, not the operator

Why it mattersHuman time on a normal Monday is zero — effort goes into tuning the editorial bar in the prompt, not into running the machine.
  • One-time setup, already done: first push to store credentials, install the LaunchAgent, enable Pages, set base_url
  • Monday: read the report, click the live link — that's it
  • Optional 3–5 min: paste the Markdown into Medium with a canonical URL (the only step Medium's API won't automate)
  • To change the voice or sources, edit one prompt file — the next issue follows
🧱 What's built — six pieces
01
render.js — one build script: issue JSON in → interactive page, email-safe twin, Medium Markdown, and the archive index out.
02
SKILL.md — the agent's entire job in one prompt: source classes, the Signal bar, the schema, the voice, the edge cases.
03
com.signal.autodeploy — the LaunchAgent that turns "file changed" into "site published" with no human present.
04
deploy.sh — stage, commit, push. Boring on purpose; boring is what you want at 7am with nobody watching.
05
GitHub Pages — free hosting for every issue plus the always-current archive. Four issues live so far.
06
SYNDICATION.md — the Medium runbook: paste, set canonical URL, keep all SEO credit at home.
The one manual step

Medium won't let robots set canonical URLs

So the single remaining human touch is a 3-minute paste — which conveniently keeps every search-engine point aimed at Signal's own archive. Everything else ships itself.
